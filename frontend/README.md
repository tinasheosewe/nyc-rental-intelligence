# Web app

The browser client for the listings API: Next.js 16 (App Router), React 19,
TypeScript and Tailwind CSS 4. The UI carries the project's working brand,
RESIDE.

## Run

Needs Node 20.9 or newer and the API running on port 8000 (see the
repository README).

```bash
npm install
npm run dev          # http://localhost:3000
```

The browser only ever calls `/api/*` on its own origin. `next.config.ts`
rewrites those requests to the backend at `NEXT_PUBLIC_API_URL`
(default `http://localhost:8000`).

```bash
npm run build && npm run start    # production build
npm run lint
```

The build downloads the Geist font from Google Fonts (`src/app/layout.tsx`),
so it needs network access.

## What is in `src/`

- `app/` — the single page. Desktop is three panels (list, map, detail);
  below the `lg` breakpoint it is one column with the map as an overlay.
- `components/layout/` — list panel and cards, detail panel, filter sheet,
  settings (boost up to two score groups, ignore dimensions, kids mode),
  the shortlist tray.
- `components/explore/` — feed (one listing at a time) and scan (grid)
  views used on small screens.
- `components/queue/` — watchlist and shortlist grids.
- `components/compare/` — compare modal with table, flags and radar tabs
  (Recharts).
- `components/map/` — Leaflet map on a CARTO basemap, listing pins, and
  `HeatmapLayer`, which draws the precomputed score grids in
  `public/heatmap/` as a tile layer.
- `lib/store.ts` — Zustand store. Watchlist, shortlist, skipped listings,
  the compare selection and scoring preferences persist in `localStorage`;
  listings, filters and UI state do not.
- `lib/useUrlState.ts` — keeps tab, selected listing, sort, filters and
  preferences in the query string, so a URL reproduces a view.
- `lib/types.ts` — response types mirroring `api/models.py`, plus the
  dimension labels and groups.

`public/heatmap/*.json` are generated by
`scripts/generate_heatmap_scores.py` in the repository root.
